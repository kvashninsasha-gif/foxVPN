# Проверки foxVPN iOS 0.1.0

Исторический отчёт. Актуальные результаты и физическая приёмка: [0.1.1](verification-0.1.1.md).

Дата: 2026-10-03. Mac Apple Silicon; Xcode 27.0 (27A266a), iOS SDK/Simulator 27.0, Go 1.25.5, XcodeGen 2.46.0. Минимальная цель iOS 16.0 означает совместимость компиляции; запуск на iOS 16 не проверялся.

## Выполнено

| Проверка | Результат |
|---|---|
| Swift package | 13 тестов без ошибок: парсинг IPv6/Reality, строгий UUID, TLS-параметры, дубли, атомарный импорт, IDN/правила, настройки JSON desktop, DNS wire и Base64 подписок |
| Реальное ядро Libbox в iOS Simulator | Конфигурации TCP/WS/gRPC × 4 режима (12 сочетаний) приняты; неизвестный тип outbound отклонён |
| Нативный DNS-SD | Запрос A `example.com` через публичный DNSService API успешно вернул запись в симуляторе; отмена запроса корректна |
| UI | Импорт публичного тестового сервера, статус, запрет фиктивного VPN в симуляторе, добавление wildcard-правила; неверная ссылка оставляет окно импорта и показывает ошибку |
| Сборка Simulator | Приложение и встроенный Packet Tunnel Extension, arm64, успешно |
| Сборка iPhoneOS Release | Приложение и Packet Tunnel Extension, arm64, успешно; `CODE_SIGNING_ALLOWED=NO`, без provisioning |
| Ядро | Собрано из включённого upstream архива 1.14.2 с проверкой SHA256; обе arm64-платформы в XCFramework |
| Значок | 1024 × 1024 PNG, RGB без alpha; геометрия существующей лисы на щите адаптирована под iOS |

Локальные полные журналы и xcresult находятся вне Git в рабочем каталоге; они не публикуются. В автоматических проверках использованы только `example.com`/`example.ru`, тестовый UUID и синтетические ключи. Пользовательские профили с Mac не копировались. Нативный DNS-тест в симуляторе проверяет API и код упаковки ответа; это не доказательство отсутствия DNS-утечек на iPhone.

В первом engine-тесте ошибочно предполагалось, что sing-box отклоняет произвольную строку UUID. Ядро допускает её; foxVPN требует корректный UUID до генерации конфигурации, что проверено отдельно. Дополнительный UI-тест выявил перекрытие окна импорта общей alert при неверной ссылке; ошибка теперь показывается внутри окна импорта.

## Что блокирует физическую приёмку

На этом Mac нет действующего сертификата подписи iOS; доступен обычный Apple ID. Physical iPhone не доступен для разработки. Network Extensions не поддерживаются Personal Team — [официальное разъяснение Apple DTS](https://developer.apple.com/forums/thread/128767). Нужна команда Apple Developer Program и provisioning для app/extension, App Groups, общего Keychain. Сборка без подписи не является устанавливаемой IPA. Никакая оплата, регистрация, вход в Apple Account или публикация в App Store не выполнены.

## Приёмка после подписи и подключения iPhone

1. Установить оба target через Xcode; проверить совпадение Team/App Group/Keychain Group, системное добавление VPN-конфигурации, импорт собственного рабочего VLESS-сервера.
2. В режиме VPN подтвердить внешний IPv4/IPv6 телефона через сервер; отдельно проверить DNS. Сохранить приватный отчёт без публикации IP/URI/ключей.
3. В smart проверить `.ru`, `.su`, `.рф` напрямую, зарубежный домен через VPN; проверить приоритет пользовательских exact/wildcard исключений, DNS и реальную маршрутизацию. IP без определённого домена использует маршрут по умолчанию.
4. Проверить TCP TLS/Reality с реальным сервером; WS/gRPC — только с соответствующим сервером, не считать принятие JSON сетевой проверкой.
5. Wi-Fi → cellular → Wi-Fi, отсутствие сети, сон/блокировка, перезапуск интерфейса и работа в фоне; проверить восстановление, HTTPS-проверку и счётчики.
6. Остановить сервер, затем отдельно аварийно остановить extension; измерить наличие/отсутствие выхода в обход при `includeAllNetworks` on/off. Не называть эту политику проверенным Kill Switch до результата.
7. Проверить On Demand и явный Disconnect; профиль не должен сам подключаться после намеренного отключения. Отдельно проверить перезагрузку и доступность Keychain до/после первой разблокировки.
8. Отклонить доступ камеры, проверить QR scan на физической камере, файл JSON/text через Files, подтверждение замены/отмену, отказ Keychain/provisioning без потери профиля.
9. Обновить собственную HTTPS-подписку, ошибки сети/TLS/redirect, повреждённые/слишком большие данные, сохранение избранного/выбранного сервера; при ошибке прежние серверы остаются.
10. Измерить память/нагрев/энергию при загрузке и больших списках правил. Лимит ядра 40 MiB требует реального замера.

Повторных macOS Keychain-диалогов здесь нет: iOS использует собственную модель общего Keychain. Это не обещание отсутствия всех системных запросов: VPN-конфигурация, камера, Developer Mode и доступ после первой разблокировки управляются iOS.
