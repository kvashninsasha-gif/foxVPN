# Desktop update channels

С 0.1.22 Windows CI запускает 72 публичные конфигурации на ядре из настоящей NSIS-установки и воспроизводит старый отказ DNS. Вместе с EXE нужно скачать `windows-core-startup.json`: `package-windows-update.py` требует этот отчёт рядом с установщиком и проверяет точную версию, SHA256 файла и полноту проверок до подписания. Отсутствующий, устаревший или относящийся к другому EXE отчёт блокирует выпуск. Приватный updater-ключ остаётся на машине выпуска; отчёт не содержит профилей пользователя. Отчёты запуска Mac/Windows включаются в новый релиз как проверяемые доказательства.

`windows.json` — отдельный канал предварительных Windows x64-релизов начиная с 0.1.20. Кнопка «Проверить обновления» расположена на «Обзоре» и в «Настройках» обеих платформ. Проверка при запуске отключается пользователем; скачивание и установка начинаются только после отдельного согласия. Windows 0.1.19 и более ранние версии нужно один раз обновить вручную.

Windows принимает только официальный `v<version>/foxVPN_<version>_x64-setup.exe`, проверяет подпись исходным ключом и версию из подписанного trusted comment. До запуска установщика сохраняется профиль, останавливаются ядро и отдельный процесс восстановления прокси, восстанавливается прежняя настройка WinINet. Если остановка/восстановление не подтверждены, установщик не запускается. После запуска установщик NSIS показывает прогресс и перезапускает приложение; отмена скачивания доступна до начала установки. Ошибка запуска установщика оставляет VPN отключённым, его можно подключить снова. Автоматического отката приложения Windows нет.

Установщик Windows собирается на disposable runner, где отдельно проверяется обновление 0.1.19 → текущая версия с сохранением файла профиля. Затем installer `.exe` подписывается локально: `python3 scripts/package-windows-update.py /path/to/foxVPN_<version>_x64-setup.exe --out-dir /path/to/new-release --notes-file /path/to/public-notes.txt`. Скрипт создаёт `.exe.sig` рядом с установщиком и `windows.json`. Приватный ключ остаётся на Mac и в CI не передаётся. Публикуйте новый релиз, проверьте digest всех assets и только затем обновляйте оба feed. Подпись обновления не является Windows Authenticode; полная приёмка встроенного обновления на личном ПК выполняется отдельно.

## macOS

`macos.json` — отдельный канал предварительных desktop-релизов Apple Silicon. Приложение читает его по HTTPS после запуска (можно отключить в настройках); скачивание и установка требуют отдельного согласия. iOS-релизы и GitHub `/releases/latest` не используются.

Архив проверяется Tauri updater по встроенному публичному ключу и версии в подписанном trusted comment (`requireSignedVersion=true`). URL должен точно соответствовать `v<version>/foxVPN-<version>-macOS-arm64.app.tar.gz` этого репозитория. Затем проверяются версия/идентификатор `.app`, подпись macOS и наличие ядра/компонента.

## Выпуск следующего обновления

1. Повысить desktop-версию в Cargo/package/tauri/locale; выполнить тесты и собрать приложение вместе с сетевым компонентом. iOS-версию не менять.
2. Закреплённое сетевое ядро и helper должны быть подписаны с Hardened Runtime. Выполнить `python3 scripts/seal-macos-bundle.py target/release/bundle/macos/foxVPN.app` **до** упаковки/подписи обновления.
3. Сохранённый приватный ключ — `~/.config/foxvpn-release/updater.key`, права 0600, каталог 0700. Он не входит в Git/архивы. Использовать исходный ключ; потеря/замена потребует ручной миграции установленных клиентов. Пароль при наличии передаётся окружением `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, а не в публичных командах/логах. Публичный ключ находится в `tauri.macos.conf.json`.
4. Собрать публичный генератор `cargo build --locked --release --example startup-fixtures`. Затем `python3 scripts/package-macos-update.py target/release/bundle/macos/foxVPN.app --startup-generator target/release/examples/startup-fixtures --out-dir /path/to/new-release --notes-file /path/to/public-notes.txt`. Перед подписанием скрипт обязательно запускает оба ядра **из готового app** на 72 комбинациях настроек каждое и воспроизводит старый отказ; пропуска проверки нет. Отчёт `macos-core-startup.json` содержит SHA256 ядер. Это проверка старта DNS/маршрутизации без создания TUN и внешних запросов, а не системная проверка утечек. Скрипт создаёт `.app.tar.gz`, `.sig`, `macos.json` и SHA256. Приватный ключ не публиковать и не передавать в CI.
5. Создать **новый** GitHub release `v<version>` с этими файлами, обычным ZIP приложения, исходниками и SHA256SUMS. Проверить digest каждого asset. Не изменять архивы/подпись существующего релиза.
6. Только после доступности всех файлов скопировать созданный `macos.json` в `updates/macos.json`, создать отдельный коммит и push. Не писать обещанную версию без опубликованной подписанной сборки. Проверить HTTPS feed и скачивание из GitHub.

С 0.1.7 приложение заменяет `.app` атомарным обменом macOS (`RENAME_SWAP`): путь установленного приложения остаётся занят даже при прерывании операции. Предыдущая копия сохраняется в `.foxVPN-previous-<UUID>.app` рядом; если переименование резервной копии не удалось, она остаётся в `.foxVPN-update-<random>/foxVPN.app`. Каталог подготовки сохраняется перед обменом и не удаляет старую копию при завершении процесса. При отказе обмена прежнее приложение остаётся на месте; небезопасного запасного варианта с двумя перемещениями нет. Файловая система должна поддерживать обмен. Во время замены выход из меню и обычные запросы завершения блокируются; перезапуск после установки разрешён. Принудительное завершение процесса средствами macOS блокировать нельзя. Резервные копии можно удалить вручную после проверки новой версии; автоматического отката при сбое запуска нет. Обновление не меняет зашифрованный профиль. Установка требует права записи в каталог приложения; при запуске с read-only образа, AppTranslocation или защищённого каталога предлагается установить в `~/Applications` либо обновить вручную. Пароль администратора не собирается приложением.

После успешного обновления новый CDHash требует подтверждения сетевого пакета macOS; интерфейс предлагает открыть штатный установщик. При незавершённой миграции автоматическое подключение откладывается, явное подключение остаётся доступно. Системный Keychain также может запросить доступ из-за ad-hoc подписи. Developer ID/нотарификация не выполнены; подпись обновления подтверждает происхождение архива и не заменяет эти механизмы Apple.

## macOS 0.1.23 и протокол компонента 4

Один раз установите новый компонент из app. Дальнейшее встроенное обновление проверяет подписанные bytes в GUI и root-сервисе, атомарно меняет root-owned slot и подтверждает запуск/привязку новой app до её замены. Используется исходный updater-ключ; root не принимает ключи или места установки из IPC. Допускается повтор того же архива для завершения прерванного перехода, откат версии и другие bytes известной версии запрещены. При отказе запуска slot возвращает отдельный watchdog. Новый GUI убирает прежний CDHash и backup. Keychain остаётся защищённым и может запросить доступ из-за ad-hoc подписи. Ручная замена app в обход этого механизма не обещает автоматической перепривязки. [Разбор и границы проверки](../docs/verification-0.1.23.md).
