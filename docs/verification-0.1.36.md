# foxVPN 0.1.36 — восстановление после задержки определения приложения

## Исправление

В 0.1.35 истечение секундного тайм-аута process lookup закрывало общий inherited socket. Последующие соединения не могли определить приложение и попадали в fail-closed reject до перезапуска ядра. Исходный дефект воспроизведён на точном production Go-коде с задержкой ответа 1,2 с, без изменения пользовательской сети. Это подтверждает дефект, но не доказывает причину конкретной прошлой сессии, журнал которой отсутствует.

В новом ядре один ограниченный worker владеет чтением и записью канала. Короткий caller timeout/отмена не закрывает transport: worker дочитывает запоздавший ответ и только затем обрабатывает следующий запрос. Ответы возвращаются через отдельные буферизованные каналы, поэтому результат старого соединения не присваивается новому. Отменённые запросы в очереди не отправляются. Close закрывает сокет и разблокирует ожидание. Действительно повреждённый/зависший transport ограничен отдельным пятисекундным deadline и остаётся fail closed.

Правила маршрутизации, неизвестные владельцы, исключения приложений, torrent policy и PF не ослаблены. Отказ определения приложения не превращается в разрешение отправить неизвестный torrent через VPN. Нуждающееся в восстановлении конкретное соединение может потребовать повтора; гарантия отсутствия любых обрывов не заявляется.

## Проверки

Шесть Go-регрессий с race detector обязательны в build-core.py для macOS: поздний ответ и успешный следующий запрос; отмена и очередь; 16 параллельных запросов; Close при ожидании; неизвестный владелец и успешное продолжение; повреждённый ответ. Native CI дополнительно проверяет настоящее разделение маршрутов после privilege drop. Результаты итоговой сборки и системной проверки фиксируются перед выпуском.
