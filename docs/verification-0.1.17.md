# foxVPN 0.1.17 — диагностика браузерного прокси Windows

При работающем локальном ядре браузер может продолжать прямое подключение. Windows-версия теперь отдельно показывает готовность локального прокси и параметры ручного прокси Windows. Проверка читает только текущие пользовательские ProxyEnable/ProxyServer/AutoConfigURL, возвращает признаки без сохранённых адресов и не меняет реестр. Кнопка открывает фиксированный ms-settings:network-proxy. Протокольная запись считается совпадающей только для HTTP и HTTPS на активном порту 127.0.0.1.

Сохранённый PAC URL не доказывает, что сценарий включён. Интерфейс предупреждает о возможном переопределении маршрута сценарием, расширением или настройками программы. При отключённом ядре и включённом ручном прокси показано предупреждение о необходимости подключить приложение либо восстановить настройки Windows. Smart направляет .ru/.su/.рф напрямую.

Локальная проверка macOS: 89 Rust-тестов, 41 frontend-тест, TypeScript/Vite build, cargo clippy --workspace --all-targets -- -D warnings прошли. Windows-специфичная проверка реестра использует уникальный временный HKCU-ключ и не меняет реальные настройки сети. Проверка на Windows runner и сборка установщика выполняются отдельно.

На личном Windows ПК через Parsec версия 0.1.16 показывала действующее локальное подключение и реальные замеры 84 мс / 5.5 Мбит/с. Это не доказывает маршрут Chrome. Окно настроек Windows пока не видно в передаваемом мониторе; настройки ОС и фактический внешний IP браузера не подтверждены. Системный Windows TUN/WFP/kill switch отсутствует. Developer ID/нотарификация macOS и Authenticode Windows отсутствуют.
