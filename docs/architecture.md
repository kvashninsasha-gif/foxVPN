# Архитектура и дальнейшая работа

WebView → разрешённые команды Tauri → Rust-движок → отдельный процесс sing-box.

GUI не получает доступ к произвольному shell. Приложение загружает локальные ассеты; CSP запрещает внешние скрипты и сетевые запросы WebView. Серверы обрабатываются как данные, React экранирует имена и журнал. Управление ядром выполняется прямым запуском с массивом аргументов, без shell-интерполяции.

Профиль шифруется AES-256-GCM со случайным 96-битным nonce. 256-битный ключ находится в Keychain/Credential Manager. Резервная копия JSON экспортируется только по действию пользователя в новый файл. Временные конфигурации используют случайные имена, каталог 0700 и файл 0600 на macOS. На Windows ACL временных файлов наследуется от пользовательского каталога; отдельное ограничение ACL не реализовано. Локальный статистический API привязан к 127.0.0.1, защищён случайным токеном и не допускает CORS для веб-страниц.

Маршруты и DNS строятся из единого списка правил: в Умном/Пользовательском режиме явные пользовательские правила идут по порядку, затем российские зоны (только в Умном), затем VPN. Глобальные VPN/Напрямую режимы имеют приоритет над исключениями. DNS имени самого VPN-сервера использует системный resolver для начального подключения; это необходимое bootstrap-разрешение, а не обещание отсутствия любых системных DNS-запросов.

Проверка задержки запускает отдельное ядро с глобальным VPN-маршрутом без TUN. Запросы выполняются через SOCKS5h, чтобы имена тестовых сайтов разрешались через прокси. Проверка скорости измеряет скачивание ровно 10 МБ, без фиктивного upload и потерь.

## До готового MVP

1. macOS: подписанный отдельный helper, установка через ServiceManagement с явным системным разрешением, проверка audit token/code signature IPC-клиента; запуск только доверенного ядра и типизированной модели настроек. Не принимать произвольные конфиги, пути к бинарникам или shell-команды от WebView.
2. Windows: служба с минимальным набором прав, ограниченный named pipe с проверкой клиента, доверенный пакет Wintun, восстановление маршрутов/метрик и IPv6 после остановки.
3. Kill Switch: отдельный механизм блокировки, который сохраняется при падении GUI или ядра. На macOS это требует отдельного решения с PF/Network Extension и учётом системного PF; на Windows WFP. Нельзя считать strict_route эквивалентом Kill Switch.
4. Транзакции обновления защищённых системных правил: подготовка блокировки → запуск ядра → установка маршрутов → проверка связи. При сбое сохранять блокировку защищаемого трафика; при явном отключении восстанавливать предыдущее сетевое состояние.
5. Тесты аварии ядра/helper, сна/пробуждения, смены интерфейса, недоступной сети, аварийной перезагрузки, утечек DNS, IPv6, UDP/QUIC, конфликтов с существующим VPN и отмены прав администратора на обеих ОС.
6. Сборка и проверка Windows 10/11 x64 и Intel Mac; подпись Developer ID/notarization и Authenticode с пользовательскими сертификатами.
7. Мастер первого запуска вместо текущего начального экрана; единая процедура включения TUN и защиты.

## После MVP

GeoIP/GeoSite на базе версионированных rule-set, QR камеры (сейчас импорт изображения), правила процессов, стабильные группы резервов, история измерений/сеансов, периодическое обновление при запуске, подписанные обновления ядра, защита резервной копии паролем и Multi-VPN. Outbound уже собирается отдельно от GUI, но публичный контракт multi-outbound ещё не реализован.
