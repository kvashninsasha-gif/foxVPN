# foxVPN 0.1.31 — маршруты, Windows-приложения и Обзор

Исходники конечного desktop-выпуска: `516c64248dd4732480583d095e2e299a0fa61d85`. Предварительная сборка для macOS Apple Silicon и Windows x64. [Релиз опубликован](https://github.com/kvashninsasha-gif/foxVPN/releases/tag/v0.1.31); все 15 assets сверены по размеру и SHA256 до переключения каналов обновления.

## Поведение

Карточка подключения стоит перед настройкой прокси Windows. В Windows можно выбрать локальный `.exe` нативным диалогом: исключение действует на обращения выбранного процесса к локальному прокси foxVPN. Совпадает полный путь без учёта регистра, а не имя/маска/каталог; вспомогательные исполняемые файлы выбираются отдельно. Данные Mac и Windows хранятся раздельно в зашифрованном профиле. Сохранение блокируется при активном/начинающемся соединении, устаревшем списке и конкурирующем изменении профиля.

Явные правила сайтов действуют во всех режимах. Точный домен важнее маски, более конкретная маска важнее общей. Затем применяются исключения программ, затем стандартные правила режима. Preview и конфигурация ядра используют общий порядок; DNS-правила следуют ему же. Неуспешный маршрут `vpn` не заменяется на `direct`. DNS hijack остаётся служебным правилом перед пользовательской маршрутизацией.

## Проверки

- 197 локальных Rust с настоящим закреплённым ядром; 15 специальных испытаний отдельно от обычного набора. Реальные HTTP-запросы проверяют `direct` и `vpn` во всех четырёх режимах при недоступном VLESS-сервере: прямой маршрут работает, защищённый не обходит сервер.
- 115 UI, TypeScript/Vite и Clippy `-D warnings`. Проверен порядок карточек Windows, выбор `.exe`, явное сохранение и сохранность черновика.
- [macOS native CI](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/39933237902): core startup и root TUN TCP/UDP после сброса UID, без изменения сети пользовательского ноутбука.
- 165 обычных Windows Rust, отдельно 2 original signature-cache и 1 native proxy/parent-death; NSIS update с 0.1.19 на 0.1.31 сохранил профиль. Ядро из установленного Windows-пакета прошло 72 startup-конфигурации, конечный GUI — 6 inference/повреждение/размер/лишние поля/parent-death. Конечная оригинальная подпись установщика дополнительно проверена с отклонением повреждения и подмены версии.
- [Windows native CI](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/39933237936): выбранная копия `.exe` работает напрямую через локальный proxy; другой исполняемый файл с похожим именем не получает обход. Явный маршрут сайта через VPN блокирует direct даже у выбранного `.exe`.
- [Frontend native CI](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/39933237976), [перенос профиля](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/39933238042), [IPC boundary](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/39933237910).
- [Dependency gate](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/39933237889): отозванная `clipboard-win 5.4.1` заменена на совместимую `5.4.3`; прежние два точных Linux-only замечания остаются видимыми. Проверка исключений не ослаблялась.
- Оба ядра из конечного Mac app прошли по 72 startup-конфигурации. Конечный GUI прошёл 6 настоящих inference и проверки повреждённой модели, лишних полей, размера и parent-death cleanup. Подписанный Mac-архив прошёл установку во временную папку, отклонение повреждения/подмены версии и подготовку компонента во временном store.

## Ограничения

Windows остаётся локальным прокси. Программы, игнорирующие его, настройки сторонних proxy/PAC и защищённые процессы с недоступным определением владельца не превращаются этим изменением в системный VPN. Если процесс не определён, исключение не срабатывает. Windows TUN/WFP, Authenticode, Developer ID и нотарификация не добавлены. Изменённые правила требуют сохранения при отключённом VPN и нового подключения; старые соединения приложения нужно открыть заново. Физический Windows-ПК и пользовательская Windows App/RDP не объявляются принятыми тестами runner.
