# Инспекция разрешений — 0.1.2

## Исправленная причина повторов

В 0.1.1 каждое сохранение профиля создавало новый `Vault`, который повторно читал `master-key` из Keychain / Credential Manager. Выбор сервера, избранное, сохранение правил, настроек и результатов измерений могли повторно вызвать диалог доступа macOS.

В 0.1.2 приложение создаёт один общий `Vault` при запуске и использует его для всех сохранений. После первого успешного обращения ключ хранится только в памяти процесса. Файл профиля остаётся зашифрованным AES-256-GCM; постоянный ключ остаётся в хранилище ОС. Буфер кеша и временные буферы ключа используют `Zeroizing`; ключ не передаётся в WebView или журналы. Конкурентные обращения защищены mutex: они не создают несколько ключей. Отказ доступа не кешируется, новый ключ вместо недоступного не создаётся.

## Проверенные точки запроса

| Действие | Поведение |
| --- | --- |
| Чтение существующего профиля при запуске | Один успешный доступ к ключу на время работы общего Vault; macOS может показать системный диалог. |
| Выбор сервера, избранное, измерения, сохранение правил и настроек | Используется ключ из памяти, повторного чтения Keychain нет. |
| Объяснение режима локального прокси | Уже было одноразовым: выбор записывается в зашифрованный профиль. Перезапуск, смена сервера и сохранение настроек не сбрасывают его. Импорт старого профиля с другими условиями защиты может потребовать нового выбора. |
| Буфер обмена | Чтение только по нажатию «Вставить», запись только по действию пользователя; автоматического чтения при запуске нет. Системные правила доступа macOS сохраняются. |
| Импорт, экспорт, резервная копия | Диалог выбора файла открывается по действию пользователя; подтверждение замены профиля сохраняется. |
| Проверка скорости | Подтверждение расхода трафика остаётся перед загрузкой. |
| Удаление сервера или подписки | Подтверждение удаления остаётся. |
| Автозапуск | Настройка меняется только пользовательским переключателем. macOS управляет уведомлением о фоновом элементе. |
| TUN, системный Kill Switch, права администратора | Компоненты пока не реализованы; приложение не устанавливает helper и не вызывает sudo или запрос администраторского пароля. |

## Ограничение подписи

Текущая сборка подписана локально (`ad-hoc`), без постоянного сертификата. Новая версия может перестать соответствовать прежнему правилу доверия Keychain, поэтому после обновления macOS может запросить доступ заново. Кеш устраняет повторные запросы от операций внутри одной запущенной версии; отсутствие диалога при каждом запуске или обновлении не гарантируется.

Для стабильного доверия между версиями требуется постоянная идентичность подписи и совместимое designated requirement; для обычного распространения вне App Store — Developer ID и нотарификация. Связь Keychain с идентичностью подписи описана в [Apple TN2206](https://developer.apple.com/library/archive/technotes/tn2206/_index.html). Доступ ко всем приложениям, отключение защиты Keychain и Gatekeeper не используются.

Обновления проекта публикуются в GitHub после проверки; порядок закреплён в [AGENTS.md](../AGENTS.md).
