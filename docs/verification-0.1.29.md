# foxVPN 0.1.29 — задержка подключения интерфейса

Дата: 15.10.2026. Подготовка исправления; сборка, публикация и приёмка новой версии пока не подтверждены. Этот документ отделяет наблюдение на установленной 0.1.28 от проверок будущего выпуска.

## Исходное наблюдение

Пользователь сообщил, что подключение через кнопку занимает больше 30 секунд или окно зависает. При отдельной проверке сетевого компонента на этом MacBook получены: остановка — 0,317 с; Start — 1,671 с; отдельная проверка доступности локального прокси — 0,635 с. Это отдельные измерения, а не сумма времени подключения через интерфейс. Они не доказывают скорость любого сервера или отсутствие всех сетевых неисправностей.

В исходном GUI синхронный `snapshot` выполнял helper IPC на потоке обработки команд; при запуске приложения также выполнялись синхронные Status/ready проверки. После уже проверенного Start GUI повторно запрашивал внешний HTTPS через прокси. Медленный ответ компонента либо дополнительного endpoint мог задержать отображение готового туннеля. Исходное наблюдение не измеряет вклад каждого из этих ожиданий отдельно.

## Проверяемое изменение

Чтение snapshot и стартовое восстановление состояния переводятся в фоновую задачу. GUI не повторяет внешнюю проверку после Start, только если компонент уже подтвердил совместимость, работающие ядро/DNS и ожидаемый порт. Для локального proxy-only режима внешняя проверка остаётся обязательной. Профиль, зашифрованное хранилище, права компонента, Keychain и условия Kill Switch сохраняют прежнюю проверку.

`traffic` уже использует async-команду и `spawn_blocking`: запрос локального Clash API имеет timeout 2 с и `no_proxy()`. Сам HTTP-запрос не выполняется на потоке WebView. Время обновления статистики нельзя выдавать за время подключения или за системную проверку утечек.

Физическая приёмка Windows-ПК по просьбе пользователя остаётся отложенной. Системный Windows TUN/WFP не поставляется обычным клиентом. Полная Mac-матрица DNS/IPv6/UDP/QUIC/sleep/reboot и publisher signatures не закрываются этим узким исправлением: [subtasks.md](subtasks.md).

Дополнительно в исходниках 0.1.29: загрузка состояния при запуске, подготовка TUN и подтверждённый выход через оба меню перенесены в фон. Первоначальная видимость окна определяется до фонового IPC; поздний ответ не скрывает уже используемое окно. Подхват существующей сессии закрывает pending intent, а позднее наблюдение старта не отменяет пользовательский Stop. Runtime не показывает здоровое подключение при отсутствии подтверждённых core/DNS/порта.

Интерфейс сразу показывает ожидающую операцию и прошедшие секунды. Отмена отправляется отдельно от ожидающего Connect, сохраняет блокировку повторного запуска до подтверждения обоих запросов и не подменяет ошибку остановки ложным «Отключено». Вкладки доступны во время ожидания. Проверки UI на отложенных ответах, ошибках остановки и настройке прокси — 108/108; TypeScript/Vite build пройден. Командная/системная приёмка окончательного установленного приложения остаётся отдельно.

Новый сценарий помощника: до «Проверить и настроить» отсутствуют обращения к ИИ и управление планом. Авторитетное поле healthy формируется backend только после действующего соединения, успешного HTTPS, отсутствия ошибок/устаревания; для Mac TUN обязательны подтверждение core/DNS/порта и HTTPS через системные DNS/маршруты без proxy (таймаут 8 с). Здоровый ответ не требует модели. При ошибке показаны шаги и план конкретных изменений до подтверждения; AI-объяснение связано с check_id, текущим stamp и сроком 120 с. Сырые технические результаты свёрнуты. Проверено 108 UI-тестов, 188 Rust-тестов; поздние ответы и истечение проверки покрыты.

16.10.2026: новый RustSec gate остановил первую неопубликованную сборку из-за RUSTSEC-2026-0346/0347/0348/0349 в rustls 0.23.45. Lockfile обновлён точечно до 0.23.46, без новых исключений. [Исправления upstream](https://github.com/rustls/rustls/releases/tag/v%2F0.23.46). Первые Mac/Windows кандидаты сохранены отдельно и не публикуются; конечные установщики собираются заново с исправленной TLS-библиотекой.

Также отключена неиспользуемая ZIP-распаковка Windows updater: канал foxVPN принимает подписанный NSIS `.exe` напрямую; tar.gz Mac остаётся поддержан. Это удаляет отозванную zip 4.6.1 из lockfile. Парсер аудита теперь сохраняет замечание YANKED с null versions как неразрешённое, а не аварийно завершается; новая регрессия подтверждает, что выпуск по-прежнему блокируется. При полном прогоне воспроизведена конкуренция за автоматически выбранный локальный порт; `CoreProcess::start` теперь сохраняет OS-резервацию порта до проверки конфигурации. Фиксированный занятый порт по-прежнему отклоняется.
