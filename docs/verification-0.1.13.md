# foxVPN 0.1.13 — сообщение о сбое подключения не остаётся после восстановления

Дата: 06.10.2026. Apple Silicon, arm64. Предварительная сборка; полный MVP по
исходному ТЗ не принят.

## Причина изменения

После нажатия «Подключиться» первая проверка связи могла не пройти: приложение
проверяет обычный HTTPS через поднятый туннель, и единственная неудачная попытка
показывала красное сообщение «Не удалось подключиться к серверу. Подробности
доступны в диагностике». Сетевой компонент в это же время продолжал
восстанавливать соединение, и через несколько секунд приложение показывало
«Подключено» — но сообщение о неудаче оставалось на экране, потому что снималось
только вручную (крестиком) или при следующем действии.

Это известное ограничение было отмечено ещё в отчёте 0.1.5 («отдельное
закрываемое сообщение о неудачной попытке сохранилось»).

Наблюдение на Mac: 06.10.2026 в 16:11 при статусе «Подключено», задержке 107 мс и
скорости 1,7 Мбит/с на экране одновременно висело сообщение о неудачном
подключении к серверу.

## Что изменено

`apps/desktop/src/App.tsx`:

- при неудаче действия подключения («Подключиться», «Включить VPN для ноутбука»,
  подключение локального прокси) приложение запоминает, что сообщение относится
  именно к попытке подключения;
- как только очередной опрос состояния показывает `connected`, такое сообщение
  снимается автоматически вместе с признаком ошибки;
- сообщения о других действиях (импорт, экспорт, настройки) этим правилом не
  затрагиваются.

## Пределы проверки

Автоматические проверки покрывают логику интерфейса, а не реальное поведение
системного компонента при восстановлении. После установки 0.1.13 CDHash
приложения меняется, поэтому macOS один раз попросит подтвердить сетевой
компонент. Developer ID и нотарификация отсутствуют.
