# Вечерняя проверка foxVPN в Windows

Сборка 0.1.19 предназначена для проверки локального HTTP/SOCKS-прокси на Windows x64. Системная служба TUN, WFP Kill Switch и автоматическое обновление Windows ещё не реализованы. Подключение в приложении не означает, что весь трафик ПК проходит через VPN.

## Установка и первый запуск

1. Скачайте `foxVPN_0.1.19_x64-setup.exe` из релиза v0.1.19 нашего GitHub. Установщик тестовый, без Authenticode-подписи; не отключайте защиту Windows. Контрольную сумму можно сравнить с SHA256SUMS:
   ```powershell
   Get-FileHash "$env:USERPROFILE\Downloads\foxVPN_0.1.19_x64-setup.exe" -Algorithm SHA256
   ```
2. Откройте foxVPN обычным способом. Для локального прокси запуск приложения от администратора не нужен.
3. В «Настройки» нажмите «Проверить сборку». Компонент должен быть найден, контрольная сумма — совпадать. Если нет, пришлите скопированную диагностику, переименовывать ядро вручную не нужно.
4. Добавьте свой VLESS/Reality-сервер. Проверьте его доступность и нажмите «Подключиться». При первом подключении подтвердите режим «Подключить локальный прокси». Выберите «Подключить и настроить Windows»: согласие сохраняется, после проверки сервера foxVPN автоматически укажет свой адрес/порт в Windows. Можно выбрать «Подключить только локальный прокси», если нужна ручная настройка. Системные TUN и Kill Switch не включаются скрытно.

## Проверка реального подключения

Пока foxVPN подключён, выполните в PowerShell (если порт изменён в приложении, замените 2080):

```powershell
curl.exe --proxy socks5h://127.0.0.1:2080 --max-time 20 --fail --silent --show-error --output NUL --write-out "HTTP %{http_code}" https://www.gstatic.com/generate_204
```

Ожидается `HTTP 204`. Это запрос через локальный SOCKS-прокси с разрешением имени через него. Затем нажмите «Отключиться» и повторите: запрос через этот порт должен перестать проходить. Команда не меняет настройки Windows. Если задан NO_PROXY для gstatic.com или всех адресов, уберите это исключение на время проверки и верните после неё.

## Браузер

Можно указать SOCKS5 `127.0.0.1:2080` в браузере, который поддерживает собственные настройки прокси, и включить разрешение DNS через SOCKS. Другой вариант — ручной HTTP-прокси Windows: «Параметры → Сеть и Интернет → Прокси», адрес `127.0.0.1`, порт из foxVPN. Эта настройка используется только совместимыми приложениями; VPN для всех программ и UDP она не заменяет. Инструкция Microsoft: https://support.microsoft.com/en-us/windows/experience/connectivity-networking/use-a-proxy-server-in-windows

В foxVPN на вкладках «Обзор» и «Настройки» есть блок проверки прокси Windows и кнопка открытия параметров. Он показывает соответствие ручного HTTP/HTTPS-прокси текущему порту, но не проверяет фактический маршрут браузера: расширения и автоматический сценарий могут его изменить. В «Умном» режиме .ru/.su/.рф идут напрямую, поэтому для проверки внешнего IP используйте сайт вне этих зон.

Перед изменением запишите прежнюю настройку прокси. После проверки верните её: при ручном режиме после отключения оставленный адрес 127.0.0.1 может мешать браузеру работать. В автоматическом режиме foxVPN восстанавливает прежние параметры при отключении, выходе и аварии основного процесса. Если прежний ручной прокси уже указывает на его текущий порт, он выключается. При внешнем изменении настроек foxVPN его сохраняет.

## Что прислать после проверки

Скопированную диагностику из настроек, версию Windows (10/11), результат `HTTP 204` при подключении и результат после отключения. Отдельно проверьте повторный запуск, сохранение серверов, тему, интервал метрик и импорт подписки. Серверные ссылки, UUID и пароли в отчёт не добавляйте. Полный профиль/экспорт конфигурации для диагностики не требуется.

Дополнительная проверка 0.1.19: несколько раз подключитесь и отключитесь, затем при подключении завершите foxVPN через Диспетчер задач. Прокси должен перестать отвечать; после нового запуска тот же порт должен быть доступен для подключения. Закрытие окна крестиком только скрывает приложение в трей — это не выход. Для обычного выхода используйте меню foxVPN. Реальные перезапуски и смену сети проверяйте отдельно; это не подтверждает отсутствие утечек или наличие системного Kill Switch.

## Если установщик не может перезаписать core/sing-box.exe

Частая причина — работающее ядро предыдущей версии. Нажмите «Прервать», отключите прокси в foxVPN и выберите «Выход» в меню приложения/трея: крестик только скрывает окно. Если старый процесс остался, завершите в Диспетчере задач только sing-box.exe из папки `%LOCALAPPDATA%\foxVPN\core`, проверив расположение файла. Другие VPN могут использовать такое же имя процесса — их завершать не нужно. После этого повторите установку актуального Windows NSIS.

Не выбирайте «Пропустить»: это может оставить старое ядро вместе с новым приложением. Если процесс не удаётся определить, перезагрузите ПК и запустите установщик до запуска foxVPN. Если ошибка сохраняется после перезагрузки, причина может быть в правах или блокировке файла; потребуется отдельная диагностика.

## Проверка автоматической настройки Windows

1. После обновления подтвердите именно автоматическую настройку; старое согласие на локальный прокси её не включает.
2. Подключитесь, проверьте ручной прокси Windows: адрес 127.0.0.1, активный порт foxVPN. Откройте 2ip.io и сравните IP с прямым подключением; расширения браузера могут переопределять маршрут.
3. Отключитесь: прежние параметры должны вернуться. Если прежде вручную был указан текущий адрес foxVPN, ручной прокси должен выключиться. Chrome должен продолжить работать.
4. На тестовом ПК при подключённом приложении завершите только основной smart-vpn-desktop.exe через Диспетчер задач. Процесс восстановления должен вернуть параметры; отдельное ядро тоже должно завершиться. Не завершайте процесс --foxvpn-proxy-guardian вместе с основным приложением: одновременное завершение обоих требует следующего запуска для восстановления.
5. Если меняете прокси вручную во время работы foxVPN, ваше изменение сохраняется при выходе.

Ошибки записи настроек или восстановления требуют проверки параметров Windows. Приложение не обещает отключение прокси при принудительном завершении сразу всех процессов пользователя, выключении питания или повреждении journal. Journal хранится в %APPDATA%\ru.smartvpn.router\windows-proxy-session.json и содержит прежние адрес/исключения/сценарий, без VPN-профиля и ключей. Не публикуйте его содержимое.

## «Проверить и настроить»

На «Обзоре» либо в «Настройках» нажмите «Проверить и настроить». При работающем VPN проверяется текущий локальный порт без переподключения. Если Windows-прокси не настроен однозначно или включены автоматические параметры, помощник предложит подтверждённое переподключение с автоматической настройкой. При отключённом VPN проверяются максимум 3 сервера; переключение на рекомендуемый выполняется отдельно. После исправления повторите проверку. Контрольный HTTPS не является полной проверкой утечек или внешнего IP браузера.
