# Контролируемый возврат Mac GUI — подзадача 2.5

Механизм добавлен в desktop-клиент 0.1.28. Он работает для обновлений, устанавливаемых **клиентом с этим механизмом** (первый обычный переход — 0.1.28 → следующая версия). Установка 0.1.28 из старого клиента сама по себе не получает новый watchdog задним числом.

При установке пользователь отдельно разрешает автоматический возврат предыдущего приложения, если новый интерфейс не подтвердит готовность за 90 секунд. Без этого разрешения сохраняется прежняя установка с резервной копией. Согласие на скачивание/обновление не считается согласием на автоматический возврат.

Перед заменой updater проверяет архив исходным ключом, строгую подпись macOS, идентификатор, тип APPL, обе версии app и thin arm64 Mach-O executable. Universal/Intel bundle и библиотека вместо исполняемого файла этого канала отклоняются. Журнал возврата дополнительно фиксирует версии/CDHash нового bundle и запечатанного приложения, совпадающего с выполняющимся клиентом. Файл приватный (0600, текущий UID), атомарно сохранён с fsync файла/каталога, ограничен 16 КиБ. Ссылки, неверный UID/режим, неизвестные поля, другие пути, неверные версии/границы попыток отклоняются.

Отдельный процесс запускается перед `RENAME_SWAP`. Журнал знает и имя будущей резервной копии, и staging-путь: авария между обменом и перемещением backup не теряет предыдущую app. Подготовленные файлы и каталоги синхронизируются до обмена; после обмена обе app сохраняются даже при отказе последующего fsync каталога. Первая смена GUI ждёт явного подтверждения frontend после успешной загрузки профиля и корневого интерфейса. Автоподключение до подтверждения блокируется. Component `FinalizeUpdate` не удаляет прежнюю CDHash-привязку до GUI readiness.

Если подтверждения нет, watchdog повторно проверяет обе app, обнаруживает GUI-процессы через kernel PID/UID, сверяет путь и строгую подпись/CDHash процесса, просит новый GUI завершиться и ждёт не более двух секунд. Неизвестный процесс или отказ безопасного завершения останавливает возврат; SIGKILL не применяется. Затем одним `RENAME_SWAP` возвращается только сохранённая предыдущая app. Отметка `restoring` позволяет завершить журнал после аварии сразу за обменом, не выполнять второй обмен. Для открытия прежней app разрешены максимум две попытки; повторных установок/возвратов по этому журналу нет. Проблемная версия пропускается при автоматической проверке обновлений; прежние update preferences сохраняются. Результат остаётся видимым до отдельного подтверждения пользователя с точным ID журнала.

Watchdog не читает профиль, ключи или Keychain, не меняет сеть, helper slots, signed version floor, updater pubkey или правила CDHash/UID. После GUI-возврата установленный новый совместимый protocol-4 helper может обслуживать разрешённую previous-CDHash app; helper не понижается. Поздняя версия профиля не заменяется backup-файлом приложения.

## Проверяемый объём и ограничения

- Локальные unit-проверки: согласие/пути/версии/лимиты, приватность и повреждение журнала, атомарная смена запечатанных временных `.app`, подмена backup/target, crash после обмена, отдельные дочерние процессы до/после обмена, сохранение update preferences и отдельное подтверждение результата. Пять integration-тестов реального App отдельно проверяют readiness после двух render frames, отсутствие подтверждения при ожидании/отказе загрузки профиля и отмену callbacks после unmount. Они не запускают пользовательский VPN или установленную app.
- Readiness означает загрузку профиля и интерфейса; это не подтверждение успешного VPN, сети, резервов или всей физической матрицы.
- Если процесс/система завершены до старта watchdog или Mac перезагрузился, незавершённый журнал возобновляется при следующем запуске клиента с этим механизмом. Фоновый launchd-agent для GUI recovery не устанавливается.
- Отсутствие/подмена предыдущей app, повреждение журнала, отказ codesign/fsync/атомарного обмена, невозможность безопасно завершить процесс требуют ручного использования проверенного архива. Helper floor не обходится ради повторной установки той же/старой версии.
- Keychain/Touch ID остаются системными окнами пользователя. Долгое неподтверждённое окно может исчерпать 90-секундный срок и вызвать согласованный возврат; доступ к ключам не расширяется.
- Реальные завершения GUI/WebView/Keychain на границах swap/restart, обновление установленной app, FileVault/reboot и совместная helper-матрица остаются отдельной приёмкой в согласованное окно. Успешный `/usr/bin/open` подтверждает передачу запуска macOS, а не работоспособность прежнего интерфейса.
