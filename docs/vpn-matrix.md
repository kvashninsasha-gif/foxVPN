# Протокол физической матрицы — подзадача 3.1

`scripts/vpn-readiness-matrix.py` создаёт 22 неизменяемых сценария для окончательной версии, связывает отчёт с SHA256 установочного артефакта, принимает наблюдения и хэши доказательств, проверяет полноту. Скрипт **не выполняет** подключение, отключение, аварии, sleep, reboot, изменение proxy/DNS/PF/маршрутов, захват пакетов или сетевые запросы. Проверка JSON и хэшей не является физической приёмкой; каждый `pass` — конкретное наблюдение оператора, которое должен проверить ревьюер по доказательствам.

Состояния `pending`, `blocked`, `unsupported`, `fail` оставляют сценарий открытым. Отсутствие нативного IPv6/UDP/HTTP3 endpoint отмечается `blocked`/`unsupported`, а не успешной проверкой. Единственное допустимое `not_applicable` — авария Mac helper в proxy-режимах, где этот компонент не обслуживает соединение. Windows-служба/TUN/WFP сюда не добавляются как реализованные: для них нужна отдельная матрица после 4.1–4.3.

## Безопасное выполнение

1. Выбрать окончательный установленный app/installer и сверить app/core/helper, версии и хэши с релизом. Сохранить собственный закрытый каталог отчёта вне Git: он может содержать реальные IP, имена интерфейсов и сетевые параметры. В Git/CI можно отправлять только специально подготовленные публичные fixtures.
2. Снять baseline при отключённом VPN только в согласованное окно: предыдущие системные proxy/DNS/PF/маршруты, рабочую сеть, прямой IPv4 и нативный IPv6. При уже работающем VPN сначала подготовить протокол; baseline и все прерывающие сценарии оставить `pending`. Не менять настройки/серверы пользователя ради проверки.
3. Использовать контролируемые endpoints с журналом времени, адресом источника и nonce запроса: IPv4-only, IPv6-only, UDP echo, HTTP/3-only, авторитативный DNS для уникального canary. Заранее подтвердить их доступность без VPN. Endpoint logs и packet capture должны позволять связать конкретный запрос с его маршрутом. Одна страница «мой IP», успешный DNS resolve или `curl --http3` с разрешённым fallback не доказывают требуемые свойства.
4. Для TUN проводить запросы обычным приложением без explicit proxy и без наследованных proxy env; сопоставить источник на endpoint с выбранным VPN/direct-маршрутом. Для proxy отдельно перечислить браузеры/версии, способ настройки и исключения. SOCKS/HTTP proxy не распространяет защиту на произвольные приложения, DNS/UDP/QUIC. Зафиксировать фактический обход вне охвата; не выдавать его за системный VPN или успешный leak-test всего компьютера.
5. Изолировать сбои сервера/резервов управляемым публичным тестовым сервером; не завершать чужие процессы. Согласованное окно прерывания записать как `authorized_window` для disruptive-case. Эти поля фиксируют уже полученное разрешение; скрипт не выдаёт и не запрашивает его. Личный Windows-ПК остаётся отложенным до нового указания пользователя.
6. После каждого сбоя сверить восстановление сети, прежних параметров и последнее намерение пользователя. Если сеть не восстановлена, остановить испытания и восстановить через поддерживаемые действия приложения/платформы. Не выключать защиту Keychain, не сбрасывать весь PF и не удалять чужие DNS/proxy/маршруты.

## Сценарии и доказательства

| ID | Действие | Минимальные доказательства и ожидаемый результат |
| --- | --- | --- |
| identity/baseline | Сверка файлов; исходная сеть | Версии + SHA256, настройки до испытаний и рабочий direct; нельзя использовать baseline другой сети/дня |
| ipv4/ipv6 | HTTPS с принудительным семейством | Endpoint source/log + запрос; IPv6 адрес не `::ffff:*` и не IPv4 ответ через API |
| dns | Новый уникальный canary | Авторитативный/resolver log и наблюдение порта 53 на физическом интерфейсе; ожидаемый resolver и отсутствие неожиданного plaintext DNS в покрываемом охвате |
| udp/quic | UDP echo с nonce; HTTP3-only | Endpoint nonce/source и согласованный HTTP/3; HTTP/2 fallback нельзя принять как QUIC |
| rules | Exact/wildcard, их приоритет, Smart/Custom | VPN и direct egress для каждого домена, порядок совпадений, default; локальный `routing::decide` не заменяет реальный маршрут |
| proxy_browsers | Поддерживаемые браузеры, bypass | Версии, proxy-конфигурация, endpoint logs и явное описание неподдерживаемого трафика |
| failover/no_reserve | Поочерёдный отказ основного и всех резервов, затем отказ всех | Временная шкала ошибок/3–60 s backoff, активный сервер и endpoint egress, отсутствие retry spin; защищённый охват соблюдает настроенную fail-policy |
| offline/wifi | Offline→online и смена сети/DNS | Новая сеть/интерфейс, bootstrap DNS refresh, ограниченное восстановление, отсутствие действия устаревшей операции |
| sleep/reboot | Реальный sleep/wake; reboot/login с auto_connect on/off | Системные временные отметки, первый запрос после wake/login, отсутствие retry burst и нежелательного подключения; восстановленная сеть |
| core_crash/gui_crash/helper_crash | Авария только процессов test-session | PID до/после, очистка прежнего процесса, recovery/backoff, собственные параметры и трафик в момент разрыва; helper нужен в Mac TUN |
| disconnect/restore | Cancel во время recovery; exit/update/uninstall | Новое намерение побеждает; previous proxy/DNS/PF/routes возвращены, сторонние изменения сохранены; обычная сеть работает |
| update | Реальный final installer/updater; отказ нового GUI | Версии/подписи/floor, сохранённый профиль, проверенный возврат, отсутствие цикла |
| backup | Публичный профиль на обеих native OS | Оба reciprocal import отчёта, JSON/manifest hashes и сохранение всех полей в разных encrypted Vault; OS credential/GUI acceptance отдельно |

Для kill-switch проверки использовать поток nonce-запросов до/во время/после сбоя и capture физического интерфейса: «первый запрос после recovery прошёл» не доказывает отсутствие утечки в разрыве. Исключения direct-правил и служебный bootstrap описывать заранее, не считать любой пакет утечкой или любым исключением оправдывать bypass.

## Формат и команды

```sh
python3 scripts/vpn-readiness-matrix.py init --scope macos-tun --version 0.1.28 \
  --artifact /private/testing/foxVPN-Mac-arm64.zip --report /private/testing/matrix.json
python3 scripts/vpn-readiness-matrix.py record --report /private/testing/matrix.json \
  --case ipv4 --result /private/testing/ipv4-result.json
python3 scripts/vpn-readiness-matrix.py check --report /private/testing/matrix.json
python3 scripts/test-vpn-readiness-matrix.py
```

Результат одного сценария содержит `status`, `note`, `observations` (все ID из `required_checks`, только явный JSON `true`), `evidence` (относительные пути файлов внутри закрытого каталога отчёта), для disruptive-case — `authorized_window`. Пути, хэши и наличие файлов проверяются; symlink/выход за каталог запрещены. Скрипт записывает результат атомарно и отказывается заменять существующий исходный план. `check` возвращает 2 при незавершённом протоколе, 0 только при полной фиксации, сообщение `physical_acceptance` всегда требует отдельной проверки операторских доказательств.

Пример **формата**, не фактический результат:

```json
{
  "status": "pass",
  "note": "IPv4 test-session nonce correlated with controlled endpoint log",
  "observations": {"native_ipv4": true, "expected_egress": true, "scope_observed": true},
  "evidence": ["evidence/ipv4-endpoint.txt", "evidence/ipv4-request.txt"]
}
```

Локально на 11.10.2026 выполнены десять unit-проверок протокола: незавершённый план, неполные/ложные assertions, отсутствие окна/доказательств, подмена хэшей/путей и symlink parent, неподдерживаемый IPv6, изменение требований, запрет наследования прежнего успешного результата, полный искусственный отчёт и допустимый proxy helper N/A. **Физическая матрица не выполнялась; текущий VPN не прерывался.** Подзадача 3.1 даёт протокол; 3.2/3.3 остаются внешней приёмкой.
