# foxVPN 0.1.34 — выбор маршрута торрентов

Проверено 24.10.2026. Код desktop-релиза: `841bfc9585ddd1d0d4ef831c89a64a8f6bf86767`. [Релиз опубликован](https://github.com/kvashninsasha-gif/foxVPN/releases/tag/v0.1.34); все 15 assets сверены по размеру и SHA256 до включения каналов обновления.

В «Обзоре» добавлен выбор «Трафик торрентов»: «Без VPN — напрямую» / «Через VPN». Булево `settings.torrents_vpn` по умолчанию false, включая прежние профили; сохраняется с профилем и участвует в configuration digest. Только явный выбор включает VPN. Во время активного подключения применяется существующая транзакция с кратким переподключением, сохранением Windows proxy lease, отменой и попыткой возврата прежнего runtime/профиля. Устаревшее ожидаемое значение отклоняется без перезаписи остальных настроек.

Выбор для распознанных торрент-клиентов и BitTorrent имеет приоритет перед пользовательскими доменами/IP, обычными исключениями приложений и общим режимом. Известные процессы маршрутизируются до sniffing, поэтому их непрозрачные TCP/UDP-данные не зависят от распознавания протокола. При недоступном выбранном выходе другой не включается. Неопределённые TCP/UDP-соединения с нераспознанным протоколом блокируются. Общий системный DNS сохраняет свою политику; собственные запросы распознанного торрент-процесса следуют его маршруту. Системный Mac-компонент должен быть не ниже 0.1.34; версия проверяется до нового Start/применения.

Mac использует существующий анонимный канал определения владельца. Для прочих подтверждённых процессов возвращается фиксированный маркер, для торрентов — отдельный маркер; реальные пути передаются только для обычных пользовательских исключений. Непривилегированный просмотр pcblist видит не все чужие процессы того же пользователя, поэтому добавлен fallback через libproc для своего UID: максимум 4096 PID, 4096 FD процесса, 32768 итераций и 200 мс. TCP требует полного совпадения tuple; неподключённый UDP допускает только однозначного владельца. Неоднозначность/неполные данные не превращаются в VPN. В IPC не добавлены команды, пути для чтения, PID от клиента или новые административные права.

## Проверки

- 216 локальных Rust с настоящим ядром, 122 UI; TypeScript/Vite, Clippy `-D warnings`. Новый C-код проверен Clang `-Wall -Wextra -Werror`.
- Реальные тестовые процессы под именами MediaGet, µTorrent/uTorrent, uTorrent Web и qBittorrent передают непрозрачные TCP/UDP-данные только прямо во всех четырёх режимах вопреки ручному VPN-правилу. У недоступного контрольного VPN-сервера зафиксировано ноль подключений; отказ direct не вызывает обход через него.
- Обратный выбор проверен настоящим локальным VLESS-сервером: клиент запрашивает закрытый порт, только сервер перенаправляет его на peer fixture. TCP/UDP проходят при явном выборе VPN, несмотря на общий direct и ручное direct-правило. Неразрешённый владелец отдельно моделируется отказом broker: трафик блокируется даже при ручном direct.
- [Mac CI](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/40110807626): шесть root-прогонов (обычное исключение, MediaGet, µTorrent; локальное перенаправление и настоящий ограниченный TUN). Ядро сбрасывает UID до 62077. Проверены основной/вложенный helper, соседний похожий пакет, TCP/UDP и приоритет torrent direct над ручным VPN. Сеть ноутбука не затрагивается.
- [Windows CI](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/40110807553): 182 обычных Rust, включая MediaGet.exe, uTorrent.exe, uTorrentie.exe, utweb.exe, qBittorrent.exe и настоящий VLESS. Отдельно 2 signature/cache и 2 native proxy/parent-death; автоматическая сессия прокси сохраняется при применении маршрутов. NSIS update 0.1.19 → 0.1.34 сохранил профиль; установленное ядро прошло 72 startup, GUI — 6 inference с проверками отказов. Подпись конечного EXE отдельно проверена с отклонением подмены payload/версии.
- [UI обеих платформ](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/40110807849), [backup](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/40110807730), [dependency gate](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/40110807733), [service boundary](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/40110807598) прошли. Обновлены Tokio 1.53.3 и Undici 8.12.3; baseline не ослаблялся, остаются только прежние два точечных исключения вне поставляемых платформ.
- Оба ядра конечного Mac app прошли по 72 startup. GUI прошёл 6 настоящих inference с закреплённой моделью и проверки отказов. Оригинально подписанный Mac-архив установлен во временный каталог, повреждение/версия отклонены; подготовка сетевого компонента проверена во временном store.

## Границы

Тестовые исполняемые файлы воспроизводят имена/пакеты программ и сетевые потоки; настоящие MediaGet/µTorrent и скачивание торрентов на устройстве пользователя не запускались. Произвольно переименованные/замаскированные программы и трафик через чужой универсальный прокси полностью не распознаются. Стандартная Windows-сборка остаётся локальным прокси: выбор применяется к трафику через foxVPN, системных TUN/WFP нет. Установленные приложение, компонент, Keychain и сеть ноутбука при сборке не менялись. Сертификаты Developer ID/Authenticode не добавлены.
