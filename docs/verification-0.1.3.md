# Проверка macOS — 0.1.3

Оборудование: MacBook с Apple M3, ARM64, 16 ГБ памяти; macOS 27.2 (26B5086k). Проверка 03.10.2026. Собрана и установлена native ARM64 `.app`; профиль и серверы сохранены. Это предварительная версия локального прокси, не системный VPN для всех приложений.

## Изменения

- Постоянный пользовательский порт (по умолчанию 2080). Он сохраняется при переподключениях; измерения серверов получают отдельные временные порты. Занятый порт отклоняется, посторонний процесс не завершается.
- Корректный Submenu для меню macOS вместо неподдерживаемых элементов верхнего уровня. Работают меню «Выход» и Command-Q с очисткой ядра и временных файлов.
- Фоновый цикл выявляет завершение ядра и восстанавливает процесс при включённой настройке. Переподключение проверяет жизнеспособность существующего процесса. Большой разрыв времени вызывает проверку после возобновления; отмена пользователем останавливает дальнейший перебор резервов.
- Опрос окна приостановлен через Page Visibility в скрытом состоянии. IPC-запросы не перекрываются; обычный опрос передаёт только состояние/порт и журнал по запросу, вместо полного профиля. Отключённое приложение опрашивается реже; фоновый цикл не копирует весь список серверов каждые две секунды.

## Автоматические проверки

48 тестов Rust, 8 тестов Vitest, TypeScript/Vite build и `cargo clippy --workspace --all-targets -- -D warnings` прошли. Включены реальные конфигурации sing-box, локальный VLESS-трафик, три последовательных запуска на одном порту, одновременные изолированные проверки, занятый порт, миграция старого профиля и настоящая изолированная запись Keychain. Тесты таймера проверили сбой процесса, модель возобновления после разрыва времени и перевод системных часов назад. Тесты окна проверили остановку опроса, возобновление и отсутствие перекрывающихся запросов.

Tauri release build и `codesign --verify --deep --strict` для архива и установленной копии прошли.

## Настоящие сетевые и нативные проверки

- В установленной 0.1.3 подключён сохранённый пользовательский сервер. После штатного восстановления прошли все 6 из 6 HTTPS-запросов: Google generate_204, GitHub и Cloudflare через SOCKS5 и через HTTP-прокси. Проверка TLS не отключалась. При контролируемом завершении ядра активные запросы прерываются; после восстановления серия повторена отдельно от инъекции сбоя.
- Через локальный API sing-box фактически наблюдались маршруты `yandex.ru → direct` и `www.cloudflare.com → vpn` в Умном режиме. Из API выбирались только проверяемые домены; пользовательские адреса/ключи не выгружались.
- Процесс ядра завершён SIGTERM, затем приложение само запустило новый процесс и восстановило HTTPS на том же порту 2080 за 1.09 секунды. Это результат данного теста, не гарантированное время для любой сети.
- Command-Q завершил приложение и ядро. Порт 2080 закрылся, временная папка с конфигурацией удалена, SHA256 зашифрованного профиля не изменился.
- После подтверждения пользователем «Всегда разрешать» выполнен ещё один полный выход и запуск той же сборки: главное окно открылось без нового запроса Keychain, сервер и настройки сохранились. Последующее подключение не требовало повторного выбора режима прокси.
- Изолированная тестовая копия с отдельным bundle identifier и Vault service проверила создание профиля, импорт публичного локального VLESS-fixture, выбор прокси, ошибку занятого порта и меню «Выход». При занятости порта рабочее пользовательское подключение сохранилось. Тестовый профиль, запись Keychain и процесс fixture удалены; дополнительный кеш сборки очищен.

## Расход ресурсов и пределы проверки

В одном замере после восстановления `ps` показал основной процесс: 102.6 МБ RSS; sing-box: 47.3 МБ RSS. Средний показатель CPU `ps` для обоих был 0.0%. Это не нагрузочный тест; отдельные процессы WebKit и пиковые значения в эти цифры не входят.

Физический сон всего Mac, выключение Wi-Fi, длительный тест на аккумуляторе и DNS/IPv6 leak-test не проводились. Разрыв времени проверен модельными тестами; настоящий сбой ядра — на установленной копии. Windows и Intel macOS не проверены. Системный TUN и Kill Switch не реализованы. Подпись остаётся ad-hoc без Developer ID/нотарификации; новая версия может снова потребовать системного подтверждения Keychain.
